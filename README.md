# Фабрика Аналитики v4.3: Контекстно-Осознанный Фреймворк с Мониторингом

## 🎯 Концепция: Саморазвивающаяся Аналитическая Фабрика

Это не просто "мульти-агентная система". Это **промышленный конвейер для производства верифицированных бизнес-артефактов**, построенный на принципах отказоустойчивости, экономической эффективности и контекстной осознанности.

Система способна не просто выполнять задачи, а **адаптироваться к провалам и самостоятельно расширять свои возможности** (создавать новые инструменты), при этом непрерывно держа в фокусе конечную цель, определенную пользователем в `config.yaml`.

**Цель этого проекта** — предоставить гибкий, самоисправляющийся и экономически эффективный фреймворк для решения сложных аналитических и бизнес-задач, сделав его работу полностью прозрачной через **интерактивную панель мониторинга**.

## 🏛️ Архитектура Системы: Динамический Граф Вычислений

Система использует `LangGraph` для построения динамического графа, который может изменять свой маршрут в зависимости от результата выполнения каждой отдельной задачи. Это позволяет реализовать сложную логику эскалации, самокоррекции и генерации артефактов.

```mermaid
graph TD
    subgraph "Фаза 1: Контекстное Планирование"
        A[config.yaml] --> B[Supervisor]
        B -->|1. Создает план задач| C{Task Fetcher}
    end

    subgraph "Фаза 2: Исследование и Самокоррекция"
        C -->|2. Берет 1 задачу| D[Task Executor]
        D -->|3. Анализ результата| E{Escalation Router}
        E -- "Успех" --> C
        E -- "Неудача" -->|4a. Эскалация Модели| D
        E -- "Крит. Неудача" -->|4b. Эскалация Архитектору| F[Architect]
        F -->|5. Исправляет/Создает Инструмент| C
        E -- "Исследование завершено" --> G[QA & Commit]
    end

    subgraph "Фаза 3: Генерация Артефактов"
        G --> H{Artifact Router}
        H -- "Есть задачи на артефакты" --> C
        H -- "Нет задач на артефакты" --> I[Janitor & Reflection]
    end
    
    subgraph "Фаза 4: Финальный Отчет"
        I -->|План выполнен| J[Final Report]
        J --> K((Готовые артефакты))
    end
```

### ✨ Ключевые Архитектурные Принципы

1.  **Контекстная Осознанность:** Вся работа системы начинается с `config.yaml`. `Supervisor` использует этот файл для создания задач, а `Researcher` и `Analyst` держат его в уме для повышения релевантности своей работы.
2.  **Верификация Гипотез:** Система не доверяет слепо входным данным, а создает состязательные задачи (`Researcher` vs `Contrarian`) для их проверки.
3.  **Каскадная Эскалация Моделей:** Задачи всегда сначала решаются самыми дешевыми моделями (`gemma-3`). В случае неудачи, система автоматически и без вмешательства человека эскалирует задачу на более мощную модель.
4.  **Динамическое Расширение Инструментов:** При столкновении с задачей, которую невозможно решить текущими средствами, `ArchitectAgent` инициирует создание нового инструмента через `ToolSmithAgent`, делая систему саморазвивающейся.
5.  **Разделение Процессов:** Основной AI-процесс (`main.py`) полностью отделен от панели мониторинга (`dashboard.py`). Они общаются асинхронно через файлы состояния, что обеспечивает максимальную стабильность.

## 🚀 Установка и Запуск

### 1. Установка

1.  **Клонируйте репозиторий и перейдите в него.**
2.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    python -m venv venv && source venv/bin/activate
    ```
3.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

### 2. Настройка

1.  **Создайте файл `.env`** и заполните его вашими API-ключами (`GOOGLE_API_KEY`, `GOOGLE_SEARCH_API_KEY`, `SEARCH_ENGINE_ID`, `SERPER_API_KEY`).
2.  **Отредактируйте `config.yaml`:** Определите вашу главную цель, контекст и гипотезы для исследования. Это **главная точка управления** всем проектом.

### 3. Запуск Системы

Система работает в двух независимых процессах. **Вам нужно будет открыть два терминала.**

**Терминал 1: Запуск AI-ядра**

*   Эта команда запускает основной процесс, который будет выполнять задачи, думать и генерировать результаты.

    ```bash
    python main.py
    ```

**Терминал 2: Запуск Панели Мониторинга**

*   Эта команда запускает локальный веб-сервер с дашбордом.

    ```bash
    streamlit run dashboard.py
    ```

После запуска второй команды в вашем браузере автоматически откроется вкладка с панелью мониторинга (`http://localhost:8501`), где вы сможете в реальном времени наблюдать за работой AI.

### 4. Варианты Запуска AI-ядра

| Цель | Команда | Действия перед запуском |
| :--- | :--- | :--- |
| **Продолжить** прерванную работу | `python main.py` | Ничего. |
| **Перезапустить** план, но **сохранить** Базу Знаний | `python main.py --new-plan-keep-kb` | Убедиться, что `output/graph_state.json` существует. |
| **Начать новую** задачу с нуля | `python main.py` | 1. Изменить `config.yaml`. <br> 2. **Удалить** `output/graph_state.json`. |

## 📂 Структура Проекта

```
.
├── agents/                     # Модули AI-агентов (Supervisor, Workers, Meta-Agents)
├── core/                       # Ядро системы (LLM Client, State, Tool Registry)
├── output/                     # Все генерируемые артефакты
│   ├── generated_tools/        # Код для динамически созданных инструментов
│   ├── api_usage_log.json      # Лог использования API
│   └── graph_state.json        # "Черный ящик" - полное состояние системы
├── tools/                      # Встроенные инструменты (web_search.py)
├── utils/                      # Вспомогательные функции
├── config.yaml                 # <-- ГЛАВНЫЙ ФАЙЛ УПРАВЛЕНИЯ ЗАДАЧЕЙ
├── dashboard.py                # <-- КОД ПАНЕЛИ МОНИТОРИНГА
├── main.py                     # Главный скрипт (AI-ядро)
├── orchestrator.py             # Логика графа LangGraph
└── requirements.txt            # Зависимости проекта
```
