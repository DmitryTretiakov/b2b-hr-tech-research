# Фабрика Аналитики v4.4: Deep Research Engine

## 🎯 Концепция: Исследовательский Институт в Коробке

Это уже не просто конвейер по обработке данных. Это **полуавтономный исследовательский институт в коробке**, спроектированный для проведения глубокого, критического анализа и производства бизнес-артефактов высочайшего качества.

Система работает по принципу **непрерывной самокоррекции**. Она не просто выполняет план, а постоянно задает себе вопросы: "Достаточно ли этой информации? Не ушли ли мы в сторону? Как улучшить курс исследования?". Этот подход, совмещенный со стратегическим распределением AI-моделей, позволяет достигать глубины анализа, недоступной для простых мульти-агентных систем.

## 🏛️ Архитектура Системы: Цикл Глубокого Погружения

В основе лежит `LangGraph`, управляющий сложным циклом, который включает в себя не только исследование, но и постоянную критику и многоэтапный синтез финального результата.

```mermaid
graph TD
    subgraph "Фаза 1: Планирование"
        A[config.yaml] --> B[Supervisor]
        B -->|1. Создает план задач| C{Task Fetcher}
    end

    subgraph "Фаза 2: Исследование и Критика"
        C -->|2. Берет 1 задачу| D[Task Executor]
        D -->|3. Успех| E{Escalation Router}
        E -- "Исследование продолжается" --> C
        E -- "Исследование завершено" --> F[Revision Node]
        F -->|4. Анализ полноты| G{Revision Router}
        G -- "Нужны доработки" -->|5a. Создает новые задачи| C
        G -- "Все хорошо" -->|5b. Переход к QA| H[QA & Commit]
    end

    subgraph "Фаза 3: Генерация Артефактов и Рефлексия"
        H --> I{Artifact Router}
        I -- "Есть задачи на артефакты" --> C
        I -- "Нет задач на артефакты" --> J[Janitor & Reflection]
    end
    
    subgraph "Фаза 4: Многоэтапный Синтез Отчета"
        J -->|План выполнен| K[Outline Agent]
        K -->|1. Создает план отчета| L{Section Writing Loop}
        L -->|2. Пишет каждую секцию| M[Final Compiler]
        M -->|3. Собирает и редактирует| N((Финальный Отчет))
    end
```

### ✨ Ключевые Архитектурные Принципы

1. **Контекстная Осознанность:** Вся работа системы начинается и сверяется с `config.yaml`.
2. **Итеративная Критика и Коррекция Курса:** Вместо QA в конце, **`ReviserAgent`** анализирует прогресс **в середине** исследования, позволяя корректировать курс "на лету", находить "слепые зоны" и добавлять новые, уточняющие задачи.
3. **Многоэтапный Синтез Отчета:** Финальный отчет не генерируется за один шаг. Он создается в три этапа: **`OutlineAgent`** создает детальный план, **`SectionWriterAgent`** пишет черновики для каждой секции, а **`ReportWriterAgent`** выступает в роли главного редактора, собирая все воедино.
4. **Каскадная Эскалация и Самокоррекция:** Система автоматически повышает уровень моделей при неудачах и способна создавать новые инструменты "на лету" с помощью `ArchitectAgent` и `ToolSmithAgent`.

## 🧠 Стратегия Распределения Моделей (Ориентация на Качество)

Для достижения максимального качества результата система использует строгую иерархию моделей, где каждая используется для задач, соответствующей ее уровню "мышления".

| Уровень Задачи | Используемые Модели | Ответственные Агенты |
| :--- | :--- | :--- |
| **1. Стратегия, Код и Самокоррекция** | **Gemini 2.5 Pro** | `Supervisor`, `Architect`, `ToolSmith` |
| **2. Глубокий Синтез и Критика** | **Gemini 2.5 Pro** | `Reviser`, `Analyst`, `SanityCheck`, `OutlineAgent`, `ReportWriter` (финальная сборка), `FinancialModelAgent`, `ProductManagerAgent` |
| **3. Генерация Текста и Фактов** | **Gemini 2.5 Flash** | `BaseResearchAgent` (извлечение фактов), `SectionWriterAgent` (написание черновиков) |
| **4. Рутинные Операции** | **Gemma 3 / Flash-Lite** | `BaseResearchAgent` (цикл ReAct), `QualityAssessor`, `Fixer` |

## 🚀 Установка и Запуск

### 1. Установка и Настройка

1. Клонируйте репозиторий, создайте и активируйте виртуальное окружение.
2. Установите зависимости: `pip install -r requirements.txt`.
3. Создайте `.env` файл и заполните API-ключи.
4. **Отредактируйте `config.yaml`** — это главная точка управления всем проектом.

### 2. Запуск Системы (2 Терминала)

**Терминал 1: AI-ядро**

```bash
# Запускает основной процесс вычислений
python main.py
```

* **Варианты запуска:**
  * `python main.py`: Продолжить прерванную сессию.
  * `python main.py --new-plan-keep-kb`: Начать с новым планом, но с сохраненной Базой Знаний.
  * Для полного сброса: измените `config.yaml` и удалите `output/graph_state.json`.

**Терминал 2: Панель Мониторинга**

```bash
# Запускает веб-интерфейс для мониторинга
streamlit run dashboard.py
```

Откройте `http://localhost:8501` в браузере, чтобы в реальном времени наблюдать за работой системы.
