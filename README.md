# Фабрика Обогащения Данных v4.2: Ресурсоэффективный Динамический Фреймворк

## 🎯 Концепция: Производство Верифицированной Аналитики

Это не просто "мульти-агентная система". Это **промышленный конвейер для производства верифицированной, устойчивой к предвзятости бизнес-аналитики**, построенный на принципах отказоустойчивости и экономической эффективности.

Проект исходит из философии **нулевого доверия к AI**: любая информация, сгенерированная LLM, по умолчанию считается черновым вариантом, требующим многоступенчатой проверки. Система реализует производственный цикл, где задачи проходят через итеративное исполнение, каскадную эскалацию моделей в случае неудачи, и финальную самокоррекцию архитектуры.

**Цель этого проекта** — не просто получить "отчет", а создать **гибкий, самоисправляющийся и экономически эффективный фреймворк** для решения сложных аналитических задач.

## 🏛️ Архитектура Системы: Динамический Граф Вычислений

Мы используем `LangGraph` для построения динамического графа, который может изменять свой маршрут в зависимости от результата выполнения каждой отдельной задачи. Это позволяет реализовать сложную логику эскалации и самокоррекции.

```mermaid
graph TD
    subgraph "Фаза 1: Планирование"
        A[Supervisor] -->|1. Создает план задач| B{Task Fetcher}
    end

    subgraph "Фаза 2: Итеративное Выполнение и Эскалация"
        B -->|2. Берет 1 задачу| C[Task Executor]
        C -->|3. Анализ результата| D{Escalation Router}
        D -- "Успех" --> B
        D -- "Неудача" -->|4a. Эскалация Модели| C
        D -- "Критическая Неудача" -->|4b. Эскалация Архитектору| E[Architect]
        E -->|5. Исправляет задачу| B
        D -- "Все задачи выполнены" --> F[QA Pipeline]
    end

    subgraph "Фаза 3: Контроль Качества и Коммит"
        F -->|6. Проверка, Исправление, Аудит| G[Commit to KB]
    end
    
    subgraph "Фаза 4: Рефлексия и Следующий Цикл"
        G --> H[Janitor]
        H --> I[Reflection]
        I -->|9a. Есть новые задачи| B
        I -->|9b. План выполнен| J[Final Report]
    end

    subgraph "Фаза 5: Финальный Отчет"
        J --> K((Готовый артефакт))
    end
```

### ✨ Семь Принципов Архитектуры "Фабрики v4.2"

1.  **Иерархическая Декомпозиция:** `SupervisorAgent` является "мозговым центром". Он декомпозирует общую цель на конкретные задачи для графа.
2.  **Специализация и Состязательность:** Вместо универсальных "экспертов" мы используем узкоспециализированных "рабочих" (`Researcher` vs `Contrarian`, `Analyst` vs `ReportWriter`).
3.  **Итеративное Улучшение:** Данные проходят через конвейер **"Проверить -> Исправить -> Снова Проверить"** в цикле QA.
4.  **Каскадная Эскалация Моделей:** **Ключевой принцип экономии.** Задачи всегда сначала решаются самыми дешевыми моделями (`gemma-3`). В случае неудачи, `Escalation Router` автоматически назначает ту же задачу на более мощную модель (`gemini-2.5-flash`) и запускает повторно.
5.  **Итеративная Обработка Задач:** Вместо пакетной обработки, граф обрабатывает **строго по одной задаче за раз**. Это является необходимым условием для работы каскадной эскалации и точечной самокоррекции.
6.  **Разделение Синтеза и Изложения:** Процесс создания нового знания (`AnalystAgent`, генерирующий JSON) полностью отделен от процесса его оформления (`ReportWriterAgent`, превращающий JSON в Markdown).
7.  **Детерминированный "Последний Штрих":** Финальная обработка цитат (`citation_post_processor`) выполняется простым кодом, что гарантирует предсказуемость и консистентность конечного результата.

## 🛠️ Технологический Стек

*   **Язык:** Python 3.11+
*   **Оркестрация:** LangGraph
*   **AI/ML:** Google Gemini API (`gemini-2.5-pro`, `gemini-2.5-flash`, `gemini-2.5-flash-lite`, `gemma-3`), Pydantic
*   **Поиск:** Google Search API с резервным переключением на Serper API
*   **Зависимости:** `requests`, `python-dotenv`, `langchain`, `langchain-google-genai`

## 🚀 Установка и Запуск

### 1. Предварительные требования

*   Python 3.11 или выше.
*   Git.

### 2. Установка

1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/ваш-аккаунт/data-enrichment-fabric.git
    cd data-enrichment-fabric
    ```
2.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    # Для Windows
    python -m venv venv
    .\venv\Scripts\activate

    # Для macOS/Linux
    python3 -m venv venv
    source venv/bin/activate
    ```
3.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

### 3. Настройка API Ключей

1.  **Создайте файл `.env`** в корневой директории проекта.
2.  **Заполните файл `.env`** вашими ключами.
    ```env
    # Ключ для моделей Gemini (Pro, Flash, Gemma, Embedding)
    GOOGLE_API_KEY="AIz..."

    # Ключи для отказоустойчивого поиска
    GOOGLE_SEARCH_API_KEY="AIz..."
    SEARCH_ENGINE_ID="..."
    SERPER_API_KEY="..."
    ```

### 4. Запуск Системы

Система запускается одной командой. По умолчанию она начинает работу с чистого листа, как определено в `main.py`.
```bash
python main.py
```

## 📂 Структура Проекта

```
.
├── agents/                     # Модули AI-агентов
│   ├── base_agent.py           # Базовый класс для всех агентов
│   ├── meta_agents.py          # Агенты высшего порядка (Architect, Janitor, ToolSmith)
│   ├── models.py               # Централизованные Pydantic-модели для валидации
│   ├── supervisor.py           # "Мозг", планировщик графа
│   └── workers.py              # Все "рабочие" агенты (Researcher, Fixer, Analyst и т.д.)
├── core/                       # Ядро системы
│   ├── budget_manager.py       # Отслеживание API-лимитов
│   ├── llm_client.py           # Централизованный клиент для вызова LLM
│   └── state.py                # Определение структуры состояния графа (GraphState)
├── output/                     # Директория для всех артефактов работы
│   ├── api_usage_log.json      # Лог использования API для budget_manager
│   └── Final_Report_v4.1.md    # Финальный отчет
├── tools/                      # Внешние инструменты
│   └── web_search.py           # Отказоустойчивый поисковый инструмент
├── utils/                      # Вспомогательные функции
│   └── helpers.py              # Парсеры, обработчики цитат и т.д.
├── main.py                     # Главный скрипт для инициализации и запуска
├── orchestrator.py             # Логика графа LangGraph (узлы, ребра, маршрутизаторы)
├── requirements.txt            # Зависимости проекта
└── README.md                   # Этот файл
```
